# Aquant 核心-卫星量化框架

> 底仓 + 波段增强（Core-Satellite）。把 swing-executor 的经验上升为「策略只产信号、单一引擎、单一成本、强制基线」的框架契约。

| | |
| --- | --- |
| **业务域** | 量化投资 / 框架化重构 |
| **技术栈** | Python / NumPy / AkShare / 迅投 QMT（文件桥接） |
| **代码位置** | `aquant/` |
| **真实状态** | 框架就绪，**未接实盘成交**，回测收益需现场跑 |

## 一、它是什么，和 swing-executor 什么关系

swing-executor 是「单点执行器」，aquant 是**把它的经验框架化**。`strategies/base.py` 的注释点明了动机：

> 上一版项目里 backtest/ 有三套回测实现、live 是第四套，零共享代码。

这是对"一个项目里回测逻辑越写越乱"的反思。aquant 的目标是：**策略只负责产信号，回测引擎、成本模型、数据层、校验层都只有一份**，谁也别想写出第二套。

## 二、Core-Satellite 策略逻辑

策略赌的是用户的主观判断——**这些标的长期趋势向上**。系统不预测方向，只做三件事：

1. **证伪**：用 MA200 判定"上涨趋势"这个假设还成不成立，不成立就走人。
2. **摊薄**：趋势成立但回调时，按阶梯分批增持，拉低底仓成本。
3. **了结**：反弹回前期高点附近时卖出波段仓，兑现价差。

收益来源是均值回归的统计特性 + 仓位纪律 + 底仓 beta + 再平衡溢价，**不是预测高低点**。

| 参数 | 默认值 |
| --- | --- |
| 底仓权重 | 0.70 |
| 波段预算 | 0.30 |
| 单标的上限 | 0.20 |
| 阶梯买入档位 | 距 60 日峰值 −5% / −10% / −15% |
| 波段了结 | 反弹回 −2% 或浮盈 ≥5% |

## 三、参数为何取这些值（有文献依据）

模块注释明确写了：**全部取业界默认值，不调参**。

- 华泰《技术面指标测试》(2021-08-19) 测了 14 个指标，滚动调参后仅 1 个仍占优——默认参数的稳健性反而更好，调参是在样本内挖噪声。
- 事前识别短期高低点需要 >70% 准确率才能跑赢买入持有（Cowles 1933 以来的择时研究）——所以策略根本不去做这件事。

## 四、回测引擎与三道校验防线

这是 aquant 工程含量最高的部分。

### 引擎：前视偏差物理阻断

`engine.py` 的 `run_backtest()` 用 `assert hist.index.max() <= signal_date` **物理阻断前视**——不是"约定不要看未来"，是"看未来直接崩"。同时建模涨跌停、停牌、T+1。

### 三道校验防线

| 防线 | 作用 |
| --- | --- |
| **Purged Walk-Forward** | 带 purge_days / embargo_days 的样本外验证，防止训练-测试数据泄漏 |
| **买入持有基线** | `BuyAndHoldStrategy` 强制对照，跑不赢"什么都不做"的策略无意义 |
| **Deflated Sharpe** | `deflated_sharpe_ratio` 惩罚"试了 N 次才试出好结果"的过拟合 |

### 成本模型

不可变 `CostModel`，ETF 免印花税（`is_stamp_tax_exempt`）；`check_order_size` 反解"最低佣金吞噬小单收益"的单笔下限——比如佣金最低 5 元，一笔 200 元的小单手续费率就是 2.5%，这个放大效应有专门的处理。

## 五、数据与 QMT 实盘桥接

| 组件 | 作用 |
| --- | --- |
| `DataProvider` 抽象 | 研究用 `AkShareProvider` + 实盘用 `QmtFileProvider`（读文件）+ `CachingProvider` |
| 复权约定 | 强制回测用**前复权**、实盘用**不复权** |
| `live/qmt_export_bars.py` | 跑在 QMT 自带 Python 3.6，导出 qfq / raw 两份 CSV |
| `qmt-realtime-pipeline` skill | 双进程架构：QMT 侧只做 IO，策略侧绝不 `import xtquant` |

::: tip 双进程架构是刻意的安全设计
迅投 QMT 的 Python 接口只能在它自带的 3.6 环境里跑。aquant 的做法是**把行情导出成 CSV，策略侧通过文件桥接**，而不是让策略进程直接 import xtquant。这样策略代码不依赖 QMT 环境，可以独立测试、独立部署。skill 里还含新鲜度闸门、交易时段闸门、安全双闸门（拒绝实盘账号）等模式。
:::

## 七、已知边界

| 边界 | 说明 |
| --- | --- |
| **未接实盘** | 框架就绪，但仓库内无实盘成交代码 |
| **策略失效场景** | 单边下跌会阶梯加仓（网格类通病，年化可达 -11%）；单边上涨只吃到 70% 底仓 beta |
| **合理预期** | 年化 6–10% 的增强收益，**不是 alpha 来源** |
| **验证缺口** | walk-forward / DSR 无独立单测，回测收益需现场跑 |

::: tip 失效场景写在了代码注释里
`core_satellite.py` 开头就写了三类失效场景：单边下跌（MA200 是第一道防线但均线滞后）、单边上涨（跑输买入持有约 26%）、震荡市才是甜区。面试时把"我知道我的策略在什么市场会死"讲出来，比"我的策略很稳"可信得多。
:::

## 九、用 Agent 协作开发的工作方式

aquant 是**和 AI Agent 协作重建的项目**，不是一个人闷头写。具体痕迹：

| 环节 | Agent 做了什么 |
| --- | --- |
| 旧项目复盘 | 把 finance trader 的 6 个 P0 翻译成 aquant 的硬约束（见 `finance trader/.workbuddy/memory/2026-09-03.md`，包含每个 P0 的文件:行号证据） |
| 架构契约 | 起草 `strategies/base.py` 的注释 + `engine.py` 的 `assert hist.index.max() <= signal_date`——把"不要看未来"从口头约定升级成物理崩溃 |
| 策略规则 | `core_satellite.py` 注释里写出三类失效场景（单边下跌 -11%、单边上涨 -26%、震荡市是甜区），并把每条规则的文献依据（华泰研报、Cowles 1933）写进代码 |
| 测试设计 | 把旧项目的两个 P0 bug 直接转成 `test_metrics.py` 的断言（Sharpe 不随笔数变、回撤峰值追踪、DSR 随尝试次数下降） |
| 数据桥接 | 把 QMT 双进程架构封装成 `qmt-realtime-pipeline` skill，**禁止策略进程直接 import xtquant** |
| 参数调整 | 明确拒绝在样本内调参；任何改动必须先走 purged walk-forward + Deflated Sharpe |

::: tip 这个项目里和 Agent 协作的硬规矩
1. 策略实现里**不能直接调下单、改仓位、算手续费**——违反 `StrategyCore.generate_signals()` 契约就是越权，回测与实盘行为必然分裂。
2. 参数必须取文献默认值，**Agent 不允许擅改**——要改就先补样本外验证，再写报告。
3. 报告必须先写"失效场景"和"不适配的标的"，再写收益——这点比 swing-executor 还严格，因为 aquant 是框架，任何含糊都会被放大。
:::

- `finance trader/.../live_paper_trader/` — 仍在跑的纸面盘矩阵，有 6 个架构级 P0，但**真实成交数据在这里**

::: tip 误判教训

## 十一、三十秒版本

> 一个核心-卫星量化框架，是上一版波段执行器的经验框架化。上一版最大的坑是 backtest 里写了三套回测逻辑、live 又写第四套，零共享。所以这一版的铁律是：策略只产信号，引擎、成本、数据、校验都只有一份。
>
> 策略是底仓 70% + 波段 30%。赌的是"标的长期向上"这个主观判断，系统只做三件事：用 MA200 证伪趋势、回调时阶梯加仓、反弹到前期高点附近了结波段仓。它不预测高低点——因为事前识别高低点需要 70% 以上准确率才能跑赢买入持有，这是 Cowles 1933 就证明了的。

> 参数全部文献默认值不调参，因为华泰的报告显示滚动调参后 14 个指标只剩 1 个还占优，调参是在样本内挖噪声。
>
> 边界我清楚：单边下跌会阶梯加仓、单边上涨只吃到 70% 底仓，震荡市才是甜区。合理预期是年化 6-10% 的增强，不是 alpha。
