# 项目知识库与本站

> Obsidian 作为唯一内容源 → 安全过滤 → 静态站发布。这个作品集站本身就是一套发布管线。

| | |
| --- | --- |
| **业务域** | 个人知识管理 / 作品集发布 |
| **技术栈** | Obsidian Markdown / VitePress / Node / TypeScript（规划中） |
| **代码位置** | 本仓库 |
| **真实状态** | **进行中**，内容已完成，自动发布管线待实现 |

## 一、为什么做这个

一开始的目标很朴素：**项目太多、笔记太散，需要一个地方说清楚我到底做过什么。**

但做着做着发现它解决的是一个更本质的问题——**私人档案和公开作品集能不能共用一份内容源**。

答案是能，但需要一层严格的过滤。

## 二、核心设计：公私隔离

```text
本地 Obsidian（完整私人档案）
        │
        │  只同步专用目录
        ↓
  发布过滤器
    ├─ 只放行 visibility: public
    ├─ 排除 draft: true
    ├─ 移除 local_path 等受限字段
    ├─ 删除「内部决策」「内部资料」等章节
    └─ 敏感信息扫描（口令/令牌/密钥/IP/客户资料/绝对路径）
        │
        ↓
  静态站构建
        │
        ↓
  公开站点
```

### 项目档案模型

每篇文档用统一的 YAML frontmatter：

```yaml
---
title: 项目名称
type: project
status: active          # active | waiting | completed | archived
area: AI与智能体
visibility: private     # private | public，只有 public 可发布
draft: false
created: 2026-08-13
updated: 2026-08-13
local_path: "本地私有字段，不进入公开输出"
priority: P1
---
```

**默认私有**——`visibility` 默认是 `private`，必须显式改成 `public` 才可能发布。这是 fail-safe 的设计。

`local_path` 字段供本地使用，任何公开构建都自动移除。

## 三、内容组织

```text
个人项目库/
├── 00-首页/        项目总览、本周行动
├── 01-项目/        按状态分：进行中 / 等待处理 / 已完成 / 已归档
├── 02-领域/        按业务域：AI、财税、RPA、GEO、产品
├── 03-决策/
├── 04-复盘/        周度复盘 / 项目复盘
├── 05-资料/
├── 90-收集箱/
└── 99-模板/
```

**主导航按项目状态组织，业务领域作为辅助入口**——这样既能快速看到下一步行动，也能按专业主题浏览长期积累。

每个项目正文固定十个章节：项目定位与背景、目标与成功标准、当前状态、本周行动、里程碑、关键决策、文档与成果、风险阻塞、复盘经验、本地路径与关联项目。

### 技术选型的变化

早期规划用的是 **VuePress 2**（因为 JavaGuide 用的就是 VuePress 系）。

实际落地改成了 **VitePress**，原因：

| 维度 | VuePress 2 | VitePress |
| --- | --- | --- |
| 构建速度 | webpack | **Vite，快一个量级** |
| 配置复杂度 | 较重 | 轻量 |
| 本地搜索 | 需额外插件 | **内置** |
| 与 JavaGuide 版式 | 同源 | 同样接近，且更现代 |

::: tip 这是一个值得讲的决策
选型不是一次定死的。规划时选 VuePress 是因为"和参考站同源"，落地时发现 VitePress 在同源的前提下**构建更快、配置更轻、搜索内置**，就换了。

**能根据落地体验修正前期规划，比一开始就选对更重要。**
:::
