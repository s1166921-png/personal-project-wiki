## 一、形态与渠道

"unified group AI customer service" 里的 **group 指的是"集团/多业务线"，不是"微信群"**。

系统**没有企业微信群接入代码**。grep 企微相关关键词只命中知识库文档。

## 二、知识方案：两套并存

这是这个项目最有技术含量的设计决策。

### 方案 A（旧版，main 分支）：标准 RAG

```text
getEmbedding → 余弦相似度 → 检索 → 拼进系统提示 → 生成
```

向量库存内存 JSON。经典 RAG 链路。

### 方案 B（新版，工作树）：直接知识上下文

**刻意放弃 Embedding 和向量库**，改为：

```text
只读取 status=approved 且 visibility=customer 的精炼 Markdown
        ↓
   按业务线作用域拼接
        ↓
   直接作为上下文给模型
```

由环境变量 `GROUP_AI_ENABLED` 切换，未开启则回退到旧 RAG。

::: tip 为什么放弃向量检索
这不是"不会用 RAG"，而是**针对场景做的取舍**：

| 维度 | RAG | 直接上下文 |
| --- | --- | --- |
| 知识规模 | 适合海量文档 | 适合**精炼后的有限知识** |
| 可控性 | 检索结果不可预测 | **检索即全部，行为确定** |
| 维护成本 | 需要调 chunk、调阈值 | 改 Markdown 就生效 |
| 出错模式 | 检索偏了会静默出错 | 知识就那些，好排查 |

客服场景的知识库**本来就是人工精炼过的**（服务范围、价格区间、流程说明），总量不大但要求准确。这种情况下，把全部知识直接给模型，比让向量检索去猜"哪段相关"更可控。

**面试时这样讲**：我知道 RAG 怎么用，也实现过；但我判断这个场景不需要它，所以砍掉了。这比"我用了 RAG"更有说服力。
:::

## 三、对话能力

| 能力 | 实现 |
| --- | --- |
| **业务路由** | `business/router.js` + `classifier.js`：LLM 分类到业务线；页面 `businessHint` 可复用，避免重复询问 |
| **多轮** | 会话历史取最近 **20 条** |
| **流式输出** | SSE，打字机效果 |
| **人工转接** | `handoffService` + 规则触发 |
| **降级** | 无知识或路由失败时返回固定引导，**不返回空白** |

### 人工转接触发规则

| 触发条件 |
| --- |
| 用户明确要求人工 |
| 询问**具体价格 / 合同** |
| 涉及**个案**的税务或法律结论 |
| 投诉、货损、赔偿 |

这几个触发条件的选择很有业务感——**该 AI 答的 AI 答，不该 AI 答的赶紧转人**。报价和个案法律结论是典型的高风险区。

## 四、安全护栏

这是我最想被问的部分。

### 输入侧：`detectInputRisk`

防提示词注入、防敏感信息泄露。

### 输出侧：`outputPolicyViolation`

对美鸥元（财税合规）业务线，输出前拦截：

| 拦截内容 |
| --- |
| 具体报价数字 |
| 保证退税结果的承诺 |
| 保证合规结果的承诺 |
| 个案税务结论 |

::: tip 为什么必须有这一层
财税合规是**强监管领域**。AI 随口说一句"这个能退税""包过"，就是实打实的法律风险，而且是对客户做出的承诺。

所以不能只靠 prompt 里写"不要承诺"——**必须有一道代码级的输出校验**。这是把合规要求从"提示词"升级成"系统约束"。
:::

### 可追溯：`traceService`

每条回答留痕**来源轨迹**——答案基于哪些知识片段生成的，出问题能倒查。

## 七、三十秒版本

> 一个双渠道 AI 客服：网页挂件用 SSE 做流式输出，WhatsApp 走 Meta 的 Cloud API Webhook。
>
> 最有意思的是知识方案。我做过一版标准 RAG——embedding 加余弦相似度，能用。但后来在新版里**主动把它砍了**，改成直接把精炼过的 Markdown 知识拼进上下文。
>
> 原因是客服知识库本来就是人工精炼的，服务范围、价格区间、流程说明，总量不大但要求准确。这种情况下，全部知识直接给模型，比让向量检索去猜"哪段相关"更可控——检索偏了会静默出错，而上下文全给你，行为是确定的，排查也容易。这不是不会用 RAG，是判断这个场景不需要。
>
> 业务侧做了路由分类，用户从哪个页面进来就带上业务线提示，不用反复问。还有人工转接规则：要报价、要合同、涉及个案税务法律结论、投诉赔偿，一律转人。
>
> 安全护栏是重点。财税合规是强监管领域，AI 随口说一句"这个能退税"就是实打实的法律风险。所以输出前有一道代码级校验，拦截具体报价和结果承诺——不能只靠 prompt 写"不要承诺"，必须是系统约束。每条回答还会留痕来源轨迹，出问题能倒查。
>
> 状态如实说：可运行原型已经完成，集团多业务线统一版在独立工作树里开发收尾，还没合并也没有部署上线。
