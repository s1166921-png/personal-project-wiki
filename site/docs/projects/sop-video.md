# 跨境 SOP 视频平台

> 国内客户上传操作视频，海外工人按货品编号搜索观看。含定价工作流、三条上传通道、HEVC 后台转码与客户隔离。

| | |
| --- | --- |
| **业务域** | 海外仓作业培训 |
| **技术栈** | FastAPI / SQLAlchemy / SQLite / Video.js / ffmpeg / Docker + Nginx |
| **代码位置** | `sop-video-system/` |
| **真实状态** | **已交付**完整可运行系统，含端到端测试 |

## 一、它解决什么问题

海外仓的工人要按标准流程操作货品——怎么贴标、怎么换箱、怎么打包。传统的做法是纸质 SOP 加口头传授，问题是：

- 海外工人**语言不通**，中文 SOP 看不懂
- 纸质流程更新慢，换一批货就要重新培训
- 工人流动性高，**培训成本反复发生**

这个系统的思路很直接：**把 SOP 拍成视频，按货品编号挂上去，工人扫码就能看。**

## 二、角色与定价工作流

这是这个项目里最有业务味道的设计。

| 角色 | 能做什么 |
| --- | --- |
| `admin` | 系统管理 |
| `approver` | 审核视频、**设定价格** |
| `customer` | 上传视频、**确认或拒绝报价** |

### 状态机

```text
客户上传
   ↓
pending
   ↓  approver 定价（set-price）
pending_confirmation
   ↓                    ↓
customer 确认          customer 拒绝
   ↓                    ↓
approved              rejected
```

**硬性规则：`pending` 状态的视频不能直接 approve，必须先走定价流。**

::: tip 为什么要有定价流
公司为客户制作 SOP 视频是要收费的。这条状态机把"报价—确认"这个商务环节**固化进了系统**：

- 审核员报价后，视频不会自动公开
- 客户在系统里确认价格，视频才对工人可见
- 客户可以拒绝，视频回到 `rejected`

它把原本靠邮件或微信来回确认的商务动作，变成了可审计的系统状态。这是技术理解业务的一个例子。
:::

`e2e_test.py` 端到端验证了这个完整流程。

## 三、三条上传通道

针对不同网络条件设计了三条路径：

| 通道 | 实现 | 适用场景 |
| --- | --- | --- |
| **multipart** | aiofiles，8MB 分块 | 常规上传 |
| **流式直写** | 边传边写磁盘，无临时文件 | 大文件，省内存 |
| **分块上传** | init → chunk → assemble | **中国 → 香港高延迟链路** |

分块上传是专门为了解决跨境上传的——大文件单次 POST 在高延迟链路上很容易超时断流，切成小块后每块独立重试。

### 转码

视频上传后检测编码，如果是 HEVC（H.265）就转 H.264：

```text
检测：读前 8192 字节，查找 hvc1 / hev1 / hevc 标记
转码：ffmpeg libx264，crf 23，+faststart
替换：转码完成后 os.replace 原子替换
超时：300 秒
降级：环境无 ffmpeg 时优雅跳过，不阻断上传
```

**为什么必须转**：HEVC 在部分浏览器和移动设备上不支持解码，海外工人用各种设备扫码，不能赌。

`+faststart` 把 moov atom 移到文件头部，让视频可以边下边播，不用等整个文件下载完——这对移动端体验影响很大。

### 安全：文件命名

```python
# file_service.py
filename = uuid.uuid4().hex + ext   # 服务端生成，不接受客户端文件名
```

**规避路径穿越**：文件名完全由服务端生成，用户输入的原始文件名只作为元数据保存，不参与路径拼接。

## 四、视频播放

::: warning 这里要如实说
README 里写"支持 HTTP Range 请求、拖动进度条"，功能**确实可用**，但实现方式是直接返回 Starlette 的 `FileResponse`——**框架原生能力**，不是自研的 Range 解析。

代码里那个自定义的 `file_iterator` 函数是**死代码**，没被调用，而且注释里自己也写了 "For proper Range support, use FileResponse instead"。

面试时不要说"我自己实现了 Range 分片"，会被问穿。正确的说法是：**用对了框架能力，并且知道为什么不要自己写。**
:::

工人端用 Video.js，支持 0.5–2x 倍速、步骤展示，以及 `?video_id=` 深链——**扫码可以直接定位到某个视频**。

## 五、客户隔离与信息安全

| 措施 | 实现 |
| --- | --- |
| 越权防护 | `_check_customer_owner`：客户只能看自己的视频 |
| 存在性不泄露 | 访问他人视频返回 **404 而不是 403**（403 会暴露"这个资源存在"） |
| 报价不泄露 | `VideoPublicInfo` 模型**不含 price 字段**，工人端拿不到报价 |

最后一条有专门的端到端断言。工人看视频是本分，但**报价是客户和公司之间的商务信息**，不能让工人看到。

## 六、认证

JWT（python-jose，HS256）+ bcrypt。

一个细节：`get_current_user_optional` 支持 **`?token=` 查询参数**认证。

**为什么**：`<video>` 标签加载视频时无法自定义请求头，Bearer Token 传不进去。所以用查询参数作为兼容通道。

这是把安全需求和浏览器限制做权衡的一个具体例子。

## 七、部署

| 配置 | 说明 |
| --- | --- |
| 基础镜像 | `python:3.12-slim`，装 libmagic1 + ffmpeg |
| 运行用户 | **非 root**（`appuser`） |
| 编排 | docker-compose：app + nginx |
| Nginx | `proxy_buffering off`（视频流式不缓冲）、`client_max_body_size 500m` |
| 健康检查 | docker-compose healthcheck |
| 持久化 | 数据卷挂载 |

`proxy_buffering off` 很关键——Nginx 默认会把后端响应缓冲完再发给客户端，对视频流来说意味着**要等整个文件缓冲完才能开始播**。关掉之后才能真正边下边播。

## 十一、三十秒版本

> 海外仓工人语言不通，纸质 SOP 和口头传授的培训成本反复发生。这个系统让国内客户上传操作视频，海外工人按货品编号搜索观看，扫码直达。
>
> 最有业务味道的设计是定价工作流。公司为客户制作 SOP 视频要收费，所以视频不能传完就公开——必须先由审核员报价，客户在系统里确认后视频才对工人可见。这条状态机把原本靠邮件微信来回确认的商务动作，固化成了可审计的系统状态，而且是硬约束：pending 状态不能直接通过审核。
>
> 技术上主要解决跨境场景的问题。上传做了三条通道，其中分块上传是专门为中国到香港的高延迟链路设计的。视频检测到 HEVC 编码就后台转 H.264，因为海外工人用的设备杂，不能赌解码兼容性，转完原子替换，没有 ffmpeg 就优雅降级。
>
> 安全上，客户只能看自己的视频，访问他人资源返回 404 而不是 403，避免泄露资源是否存在；工人端的数据模型里根本没有报价字段。
>
> 部署用 Docker 加 Nginx，Nginx 必须关掉 proxy_buffering，否则视频要等整个文件缓冲完才能开始播。
>
> 演进方向是多语界面、内置二维码、内容理解联动——让作业培训的系统化能力继续往下走。
