# FinanceTrader 多策略实盘执行矩阵

> 4 套策略逻辑，跑在 5 个相互隔离的虚拟盘账户上，每个交易日收盘后自动复盘。这是**真正在跑**的那套系统——不是回测，是逐笔落账的纸面盘。

| | |
| --- | --- |
| **业务域** | 量化投资 / 多策略组合执行 |
| **技术栈** | Python / XGBoost / 迅投 QMT 行情桥 / 多角色 Agent 决策链 |
| **代码位置** | `finance trader/strategy/live_paper_trader/` |
| **真实状态** | **运行中**，125 笔已平仓成交入账；**全部为虚拟盘，未投真钱** |

::: warning 先说清楚：这是纸面盘
所有资金均为虚拟（paper trading）。代码里明确写着 `CRITICAL: ALL TRADING IS VIRTUAL. NO REAL MONEY.`
展示它的价值不在于"赚了多少"，而在于**多策略并行时的工程治理**——资金隔离、行情新鲜度闸门、确定性执行闸门、逐笔可归因账本。
:::

两个账户跑**完全相同的策略逻辑**，但资金、持仓、收益彻底隔离。这样才能回答一个问题：同一套逻辑在不同资金规模下，表现是否一致？

答案是**不一致**：4 万账户 −0.52%，20 万账户 +0.16%。同样的信号，因为单笔金额不同，滑点与佣金的吞噬比例不同。这种对照实验是很多人不做、但很值钱的做法。
:::

## 二、V4/V14 ETF Scalper（规则驱动短线）

**核心做法**：`scalping/v4_scalper.py` —— 24 只 ETF 分五大品类（宽基/行业/主题/商品/跨境），每品类独立参数，用固定公式打分排名选**最优**标的，而不是"有信号就买"。

出场是分层的：达到动态目标 → 移动止盈锁定 → 30 分钟强制分批 50% → 60 分钟时间止损 → 收盘强平。

| 账户指标 | 数值 |
| --- | ---: |
| 统计窗口 | 2026-07-17 ~ 2026-08-27（21 个交易日） |
| 初始 → 期末 | 200,000 → 205,542 |
| 区间收益 | **+2.77%** |
| 最大回撤 | **1.27%** |
| 夏普 | 3.26（**21 天折算，参考价值有限**） |
| 年化 | +38.82%（同上，短期外推不可信） |

::: tip 两个反直觉的发现
1. **PARTIAL 50%（强制分批）是第一大盈利来源 +3,811，胜率 100%**——"到点就卖一半"这个纪律性动作，贡献超过任何一次精准的目标止盈。
2. **唯一一次止损就亏了 −2,621**，几乎吃掉全部止盈的 1/4。但**只触发过 1 次**，说明止损阈值设得偏宽——这是设计选择，不是 bug。

另外注意：**胜率 100% 的 TARGET 类出场是定义使然**（达到目标才触发），本身没有信息量；真正有信息的是 FLAT TIME STOP（32%）和 SESSION_END（39%）——这两个是"没按预期走"的出场，胜率显著更低。
:::

**盈利最集中的标的**：515050（+1,740，5 笔全胜）、513330（+1,617，6 笔 83%）、512760（+1,440，3 笔全胜）。

## 三、V17 XGBoost 多因子（机器学习选标的）

**核心做法**：`scalping/v17_ml_trader.py` —— 每只 ETF 训练**独立的** XGBoost 二分类器（因为港股创新药和黄金的价格行为完全不同，一个模型打天下无效）。用 21 维特征预测"未来 25 分钟是否上涨"，概率 > 0.55 才买。

21 维特征分四类：趋势（MACD/ADX）、动量（RSI/KDJ/ROC/CCI）、波动（布林带/ATR/Keltner）、量价（量比/OBV/VWAP偏离/MFI）。

**每天盘前用过去 2 个月的 5 分钟 K 线重新训练**，模型适应最新市场状态。

### 21 笔已平仓归因

| 指标 | 数值 |
| --- | ---: |
| 已平仓笔数 | 21 |
| 胜率 | **33.3%** |
| 累计已实现盈亏 | **−3,032** |
| 盈利因子 | 0.19 |
| 毛利 / 毛损 | +731 / −3,762 |

::: danger 这个策略目前是失败的，但要说清楚为什么
三个证据：

1. **21 笔全部是 `SELL_EOD`（收盘强平）出场**——没有一笔是主动止盈或止损离场的。这意味着 6 层止盈止损设计**从未被触发**，所有仓位都被动拖到收盘。
2. **胜率 33.3%、盈利因子 0.19**——赚的钱只有亏的钱的 1/5。
3. **所有 21 笔的预测概率都落在 0.60–0.70 区间**，没有任何一笔低于 0.60 或高于 0.70。

第 3 点最致命。如果模型输出的概率全都挤在一个窄区间，说明**概率没有区分度**——它并没有真的学会"这只 ETF 现在更容易涨"，只是输出了一个接近先验的常数。这时候用 0.55 做阈值，等于随机筛选。
:::

::: tip 模型概率分档检验（判断 ML 策略是否真有效的关键）
我专门在汇总脚本里加了这个检验：把成交按 XGBoost 预测概率分档，看高置信档的表现是否真的优于低置信档。

当前结果：**全部 21 笔集中在 0.60–0.70 一档**，无法做档位对比——这本身就是结论。一个健康的概率模型，预测值应该分散在各档，且高置信档胜率显著更高。

这个检验会随每天重跑自动更新，是判断"模型到底学没学到东西"的客观标准，不靠感觉。
:::

## 四、TradingAgents B/C/C 核心仓

**核心做法**：`tradingagents_decision.py` + `tradingagents_competition.py` —— 多角色分析师各自出报告 → 多空双方辩论 → 风控裁决给出评级 → 按评级缩放仓位（如 Overweight → 0.8 倍）→ 落纸面执行。

| 项目 | 数值 |
| --- | ---: |
| 初始资金 | 200,000 |
| 当前权益 | 188,075 |
| 累计收益 | **−5.96%** |
| 核心仓（80%） | 160,000 → 148,126（−7.42%） |
| T+0 卫星仓（20%） | 40,000 → 39,949 |

当前持仓：159915 创业板（浮亏 −2,041）、159919（浮亏 −883）、511010 国债（+24）。

::: tip 这里最值得讲的设计：执行闸门是确定性 Python
`tradingagents_decision.py` 的模块注释写得很明确：

> LLM 或外部 Agent 的输出可以作为文本喂进来，但**执行闸门是纯 Python**，这样实盘下单的安全性不依赖模型行为。

这是 Agent 做交易决策时**唯一负责任的做法**：让 LLM 参与研究和辩论，但不让它碰下单。模型可能幻觉、可能被提示词注入，但 Python 的风控规则不会。

配套还有 `tradingagents_governance.py` 做治理，以及账户里的硬性声明：
`"real_data_rule": "Trade only from real, timestamped, verified market/account data; stale/fallback/unverifiable data must hold."`
——**数据不可验证时必须持仓不动**，而不是拿假数据继续交易。
:::

## 五、TradingAgents T+0 卫星仓

**核心做法**：`tradingagents_t0_overlay.py` —— 核心仓保持不动，只额外管理一个隔离的 20% 额度做 T+0 短线。

参数很克制：止损 −2.0%、止盈 +1.2%、最长持仓 6 小时、14 只跨境/商品 ETF。

| 时间 | 标的 | 价格 | 股数 | 收益率 | 原因 |
| --- | --- | ---: | ---: | ---: | --- |
| 2026-08-12 | 513030 | 1.902 | 19,800 | −0.83% | MAX_HOLD |
| 2026-08-13 | 513050 | 1.124 | 33,200 | −0.97% | MAX_HOLD |
| 2026-08-24 | 159981 | 1.584 | 24,000 | **+1.80%** | TAKE_PROFIT |
| 2026-08-25 | 513130 | 0.567 | 66,600 | −0.53% | MAX_HOLD |

4 笔中 3 笔是 `MAX_HOLD`（持仓超时离场），只有 1 笔真正止盈。**−0.52% 的亏损基本由"拖到超时"造成。**

::: tip 行情新鲜度闸门：fail-closed 而非 fail-open
代码里 `MAX_QUOTE_AGE_SECONDS = 10`——行情快照超过 10 秒就**拒绝交易**。

日志里能看到它真的在工作：
```
"last_decision": {"action": "HOLD", "reason": "quote stale (4044.3s)"}
```

行情断了 4044 秒（约 67 分钟），系统的选择是**不动**，而不是用 1 小时前的价格假装成交。

这是纸面盘和实盘之间最容易失真的一环：很多回测假设"随时能用最新价成交"，实盘里行情断了还在交易，等于用假价格做决策。**宁可不交易，不用脏数据交易。**
:::

## 六、工程治理：这套系统真正值钱的部分

收益数字有好有坏，但这套系统的工程治理是过硬的：

| 机制 | 实现 |
| --- | --- |
| **资金隔离** | 5 个账户独立状态文件，核心仓/卫星仓 80/20 拆分；`account_migration` 专门修过"20% T+0 资金在旧账户里被重复计算"的问题 |
| **行情新鲜度闸门** | 10 秒超时 fail-closed，宁可 HOLD 不用旧价 |
| **确定性执行闸门** | LLM 只做研究和辩论，下单由纯 Python 风控裁决 |
| **数据可验证规则** | `stale/fallback/unverifiable data must hold`（不可验证数据必须持仓不动） |
| **逐笔可归因账本** | 每笔记录进出场价、持仓分钟数、出场原因、入场理由；V17 还记录模型预测概率 |
| **每日自动复盘** | `daily_review.py` / `performance_report.py` / `three_strategy_monitor.py` 收盘后自动生成 |
| **策略间互不干扰** | V4/V14、V17 各自独立状态文件与资金账户，可同日并行 |

::: tip 汇总脚本：数字不手工维护
所有上表的数字都来自 `reports/summarize_all_strategies.py`，读账本自动汇总：

```bash
python reports/summarize_all_strategies.py
```

它输出按**出场原因 / 标的 / 交易日**三个维度的归因，外加 V17 专属的"模型概率分档检验"。每天收盘后重跑即刷新，**没有一个数字是手写的**。

这与 swing-executor 的 `summarize_trades.py` 是同一套设计原则：只做汇总不做美化，归因优先于结论，可复跑。
:::

## 七、已知边界

| 边界 | 说明 |
| --- | --- |
| **全部是虚拟盘** | 未投真钱；纸面盘无真实滑点、无冲击成本、无涨跌停无法成交的真实摩擦 |
| **样本极短** | V4 的 +2.77% 只来自 21 个交易日；夏普 3.26、年化 38.8% 是短期外推，**不可信** |
| **旧项目有 6 个架构级 P0** | 见 `finance trader/.workbuddy/memory/2026-09-03.md`：最大回撤恒为 0、Sharpe 公式写成 √(252/n)、同 bar 收盘价成交、买入侧零滑点等。这套纸面盘与那批问题代码**同属一个仓库**，数据需谨慎解读 |
| **V17 目前是失败的** | 21 笔全部收盘强平、胜率 33%、概率无区分度——已如实记录，没有粉饰 |
| **TradingAgents 核心仓跑输** | −5.96%，主因是持仓集中在创业板等下跌标的 |

::: warning 面试时最诚实、也最有利的说法
"这套系统 4 个策略里，只有 1 个（V4/V14）在赚钱，V17 是失败的，TradingAgents 是亏的。我把它全部记下来，包括失败的那个为什么失败——模型概率没有区分度。

我认为这比'我的策略很赚钱'更有说服力，因为**能说清楚自己哪里输了，才说明真的在跑、真的在归因**，而不是只挑好看的数字给人看。

收益数字我不强调，因为这个样本只有 21 个交易日。我更愿意讲工程治理：资金怎么隔离、行情断了怎么 fail-closed、LLM 为什么不碰下单、每笔交易怎么归因。"
:::

## 八、三十秒版本

> 一套多策略实盘执行矩阵：4 套策略逻辑跑在 5 个隔离的虚拟盘账户上——V4/V14 规则驱动 ETF 短线、V17 XGBoost 多因子选标的、TradingAgents 多角色决策核心仓、外加 T+0 卫星仓和一个独立的 20 万 T+0 对照账户。每个交易日收盘后自动复盘。

> 结果有好有坏，我如实说：V4/V14 是 104 笔成交、胜率 66%、累计 +6,216，最大回撤只有 1.27%；V17 是 21 笔、胜率 33%、亏 3,032，而且**所有 21 笔都是收盘强平**——止盈止损一次都没触发过，模型预测概率全挤在 0.60-0.70，说明它没学到东西；TradingAgents 核心仓 −5.96%。

> 最值得讲的是工程治理，不是收益。资金隔离做对照（同一套逻辑 4 万账户 −0.52%、20 万账户 +0.16%）；行情快照超 10 秒就拒绝交易，日志里真的能看到"quote stale 4044s"然后 HOLD；LLM 只做研究和辩论，**下单闸门是纯 Python**，因为模型会幻觉、Python 规则不会；数据不可验证时强制持仓不动。

> 所有数字都由汇总脚本从账本自动跑出来，按出场原因、标的、交易日三维归因，没有一个是我手写的。失败的那个我也照记。
