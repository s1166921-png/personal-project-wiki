> 搜热点 → 抓公众号/网页原文 → DeepSeek 改写成「B2P 政策解读风」→ 事实一致性 / 原创度 / 质量校验 → 生成封面 → 导出微信 HTML。已打包成 Windows 桌面程序。

## 一、它解决什么问题

面向跨境卖家的内容创作辅助工具：把"手动搜热点、手动写文章、手动做封面"这套流程，收敛成一个**本地可用的桌面工坊**。

定位很实在——它不是服务端数据流水线，是给运营人员在本地用的写作辅助工具（已用 PyInstaller 打包成 Windows 便携 exe）。

## 二、核心管线（pipeline_core 五模块）

| 模块 | 职责 |
| --- | --- |
| `extractors.py` | 内容质量评估（`assess_article_quality`：正文够不够长、有无元数据残留、微信限制尾巴） |
| `importing.py` | 入口分类（粘贴全文 / 搜狗跳转 / 公众号直链 / 普通网页）+ 搜狗跳转解析 |
| `facts.py`（788 行） | **规则型事实一致性核查**：抽数字/日期/实体，找出改写文里有、原文里没有的事实，检测时间方向冲突 |
| `originality.py` | 原创度检测：最长公共子串 + 事实 token 掩码，`max_copied_run < 30` 判定可接受 |
| `quality.py` | 搜索结果信源质量过滤（低质域名黑名单、行业源加分、关键词相关度） |

## 三、事实核查与原创度（务必如实表述）

::: warning 这两个词要精确，别被问穿
- **「事实核查」** = 改写文与**原文**的实体/数字/时间一致性比对，**不验证客观真假**。是"自洽性校验"，不是"真实性核验"。
- **「原创度检测」** = 最长公共子串相似度，**非语义/向量**，只能抓字面照抄。

面试时把它说成"规则型事实一致性校验"和"字面照抄检测"，比笼统说"事实核查 + 原创度检测"更经得起追问。技术选型的合理性在于：这个场景不需要上 embedding 模型，规则校验够用且可解释。
:::

## 四、技术实现

| 层 | 实现 |
| --- | --- |
| 服务 | Flask（`app.py`，8527 行），路由覆盖 search / generate-article / source-evidence / repair-facts / generate-cover / to-wechat-html 等 |
| LLM | `api.deepseek.com`（DeepSeek，非 OpenAI），裸 requests 调用 |
| 抓取 | `trafilatura` + `curl_cffi`（TLS 浏览器指纹模拟，专为破微信反爬） |
| 搜索 | BeautifulSoup 直爬百度 / 360 / 搜狗 / Bing / 知乎，**无付费搜索 API** |
| 前端 | 单文件 `index.html` + `marked.min.js` |
| 打包 | PyInstaller 便携 exe（`dist/wechat-news-pipeline-portable/`） |

## 八、三十秒版本

> 一个跨境电商热点内容创作工坊，已经打包成 Windows 桌面程序。流程是：多引擎搜热点、抓公众号和网页原文、用 DeepSeek 改写成政策解读风格、过事实一致性和原创度校验、生成封面、导出微信 HTML。
>
> 事实核查和原创度我要精确地说：事实核查是规则型的——把改写文和原文的数字、日期、实体做一致性比对，找出改写文里凭空多出来的事实和时间方向冲突；原创度是最长公共子串，抓的是字面照抄，不是语义。两者的边界都做了明确声明。
>
> 搜索直接爬百度、360、搜狗，微信抓取用 curl_cffi 做 TLS 指纹模拟，是国内公开数据源的常规做法。
>
> 有个值得讲的沉淀：专门分析了 15 篇以上的爆款文章，提炼出 5 种标题公式，作为改写 prompt 的依据。这是真实的研究，不是拍脑袋。
>
> 演进方向是稳健性、补集成测试、把客观核验从"自洽"升到"真实"。
