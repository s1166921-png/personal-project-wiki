# SwingExecutor 波段执行器

> 人工观点 + 算法执行：你判断「哪些标的会涨」，系统负责「低位分批买、高位分批卖、错了止损离场」。

| | |
| --- | --- |
| **业务域** | 量化投资 / A 股波段交易 |
| **技术栈** | Python / NumPy / 腾讯后复权日线 / QMT（规划中） |
| **代码位置** | `swing-executor/` |
| **真实状态** | 首版回测完成（2021–2026 五年样本） |

## 一、它解决什么问题

做量化交易，最难的不是"算出该买什么"，而是**把一个人工观点变成可执行、可回测、不会自我欺骗的纪律**。

这个项目的定位很克制：**系统不判断标的是否会涨**。它赌的是"用户的主观判断是对的（这些标的长期向上）"，系统只负责三件事——在相对低位分批建仓、相对高位分批止盈、判断错了就止损离场。

它源自 `finance trader` 项目（HKUDS/AI-Trader 的开源研究）的经验萃取，是**从零重建的干净实现**——把旧项目踩过的坑（多套回测逻辑漂移、指标算错、成本模型不一致）一次性写死在架构里。

## 二、策略规则（文献依据见代码注释）

| 模块 | 规则 | 依据 |
|---|---|---|
| 趋势过滤 | 收盘 > MA200 才做多 | Connors【实证】 |
| 入场 | RSI(2) < 10 或 收盘 < MA20 − 1×ATR(14) | Connors / EPA 因子【实证】 |
| 分批建仓 | 3 批，间隔 1×ATR 下跌 | 常见做法（配总仓上限防 Martingale） |
| 分批止盈 | 均价 + 2×ATR(14) 卖 1/3 | 常见做法 |
| 吊灯止盈 | 持仓期最高收盘 − 3×ATR(22) 全退 | Le Beau【实证，约 73% 趋势幅度】 |
| 硬止损 | 均价 − 2×ATR(14) 全退 | ATR 自适应止损优于固定 %【实证】 |
| 时间止损 | 持仓 15 日仍亏损则退 | Connors 变体 |

::: tip 参数全部是文献默认值，刻意零优化
旧项目的教训是「在同一段数据上调参、再报告同一段数据」等于自欺。所以这里所有参数直接取公开文献默认值，**一个都没调**。换标的清单后，结论需要重新检验——这一点 README 开头就写明了。
:::

## 三、六条工程铁律（这是最值钱的部分）

这是对旧项目 6 个 P0 问题的修复，直接写死在架构里，而不是靠自觉：

| # | 铁律 | 实现 |
| --- | --- | --- |
| 1 | **信号 T 日收盘计算，T+1 开盘成交** | `decide()` 在收盘快照上算意图，次日开盘 `_execute()` 成交，回测与实盘共用同一套 `core/strategy.py` |
| 2 | **成本模型唯一** | `core/cost.py` 单文件，回测与实盘都调它，不存在两套成本 |
| 3 | **涨跌停建模** | 开盘涨停不追买、跌停卖不出，受阻次数进诊断输出 |
| 4 | **指标正确** | Sharpe 按日收益序列算，最大回撤用峰值追踪——直接修复旧项目的两个 P0 bug |
| 5 | **数据缓存双向校验** | 起止两端都覆盖才命中缓存（曾因只查末端导致回测结果漂移：118 笔 ↔ 54 笔） |
| 6 | **基准对照强制输出** | 不跑赢"什么都不做"（买入持有）的策略没有存在价值，回测必须打印对照 |

## 四、成本模型

`core/cost.py` 单一实现：

| 项 | 参数 |
| --- | --- |
| 佣金 | 万 2.5，最低 5 元 |
| 印花税 | 卖出千 1（**仅股票，ETF 免征**） |
| 滑点 | 单边 0.1% |

::: tip 为什么 ETF 免征印花税是条铁律
ETF 免印花税、无停牌/ST 风险，是波段策略的首选载体。个股往返摩擦结构上高约 5bps（印花税），只在波段空间足够大时才划算。这个判断直接影响了标的池的选择。
:::

::: tip 这张表解释了策略的全部盈亏结构
**止损的杀伤力大于止盈的贡献**——这是均值回归入场的结构性代价：买超卖本质上是在接落刀，止损是必要成本，不是设计失误。

两个反直觉的细节：
- **硬止损只有 9 次，却贡献了最大单笔杀伤**（平均每次 −9,493）。
- **时间止损 19 次、胜率 0%、平均 −2,763**——它是"温水煮青蛙"式的慢性失血，比硬止损更隐蔽。

面试时能说出这些，说明你真的跑过、真的归因过，而不只是看了一眼总收益率。
:::

## 七、"四个策略"到底在哪——完整清单

之前这一节曾误判为"只有 2 个策略、第 4 个不存在"。**那个结论是错的**，原因是只搜了新项目目录，漏掉了仍在运行的纸面盘主目录 `finance trader/strategy/live_paper_trader/`。更正后的完整清单：

| 策略 | 核心做法 | 主文件 | 状态 |
| --- | --- | --- | --- |
| V4/V14 ETF Scalper | 规则驱动 ETF 短线，多品类打分排名 + 移动止盈 + 动态目标 + 时间分批 | `scalping/v4_scalper.py` | 运行中，104 笔已平仓 |
| V17 XGBoost 多因子 | 每只 ETF 独立 XGBoost，21 维特征预测 25 分钟后上涨概率 >0.55 才买 | `scalping/v17_ml_trader.py` | 运行中，21 笔已平仓 |
| TradingAgents B/C/C 核心仓 | 多角色研究 → 多空辩论 → 风控裁决 → 仓位缩放，执行闸门为确定性 Python | `tradingagents_decision.py` + `tradingagents_competition.py` | 主账户 20 万，−5.96% |
| TradingAgents T+0 卫星仓 | 核心仓之上叠加 T+0 短线，独立风险额度，行情新鲜度闸门 10 秒 fail-closed | `tradingagents_t0_overlay.py` | 4 万，−0.52% |

外加一个**独立 20 万 T+0 比赛账户**（与卫星仓同一套逻辑，资金/持仓/收益完全隔离）用于横向对照。

所以准确说法是：**4 套不同的策略逻辑，跑在 5 个相互隔离的账户上**。详细的逐笔归因见本站 [FinanceTrader 实盘执行矩阵](./finance-trader.md) 页面。

这里（swing-executor）与 aquant 属于**新建的干净实现**，与上面那套纸面盘是并行关系：

| 项目 | 定位 |
| --- | --- |
| `swing-executor/core/strategy.py` | 波段执行器（人工观点 + 算法执行），本页主角，181 笔回测即此策略 |
| `aquant/strategies/core_satellite.py` | 核心-卫星框架，回测/实盘接口齐备 |
| `finance trader/.../live_paper_trader/` | 仍在运行的纸面盘矩阵（上面 4 套策略），已诊断 6 个架构级 P0，但**实盘成交数据在这里** |

::: tip 上一版误判的教训
我第一次核对时只在新项目（swing-executor、aquant）里找策略，发现只有 2 个，就下了"第 4 个不存在"的结论。**这是搜索范围不全导致的错误**，不是用户记错。

搜索策略类资产时，应该连"仍在运行的旧项目"一起扫，而不只看新仓库——旧项目可能问题很多，但它的**真实成交记录**恰恰是最有价值的证据。
:::

## 八、用 Agent 迭代策略的工作方式

这个项目是**和 AI Agent 协作开发**的，不是一个人闷头写。具体做法：

| 环节 | Agent 的角色 |
| --- | --- |
| 策略规则设计 | 提供文献依据（Connors / Le Beau / 华泰研报）并落到代码注释里，每条规则可追溯 |
| 旧项目复盘 | 把 `finance trader` 的 6 个 P0 问题逐条翻译成架构约束（即"六条工程铁律"） |
| 回测实现 | 单一引擎、单一成本模型，回测与实盘共用同一套 `decide()` |
| 结果归因 | 生成交易明细汇总，按出场原因/标的/年度拆解，**先解释钱怎么亏的，再谈改不改** |
| 参数调整 | 明确拒绝在样本内调参；要改就先补样本外验证 |

::: tip 一个刻意保留的原则：不让 Agent 在样本内调参
最常见的自欺是"在同一段数据上调参，再报告同一段数据"。所以这个项目里，Agent 被明确要求：

1. 参数取文献默认值，**一个都不调**；
2. 任何参数改动，必须先在样本外（purged walk-forward）验证，再进报告；
3. 报告必须先写"失效场景"和"不适配的标的"，再写收益。

这也是为什么长江电力被标注为"不适配"、2025 年的数据被如实展示——**归因优先于结论**。
:::

## 九、性能定位

策略的核心定位是**回撤控制 + 纪律执行**，不是追求超额收益。回测五年：

| 指标 | 策略 | 同期买入持有 |
| --- | ---: | ---: |
| 累计收益 | +2.24% | +37.60% |
| 最大回撤 | 2.16% | 23.77% |

适合"怕回撤、愿意牺牲部分上行"的资金；不适合"追求收益最大化"。参数全部用文献默认值（一个没调），因为旧项目最大的教训就是在同一段数据上调参再报告同一段数据，等于自欺。

## 十一、三十秒版本

> 一个波段执行器：我不预测标的会不会涨，那是我自己的主观判断；系统只负责纪律——MA200 之上才做多，RSI 超卖或跌破 MA20 时进场，分三批建仓，涨到 2 倍 ATR 分批止盈，吊灯线止损。
>
> 最有价值的不是策略本身，而是六条工程铁律——都是旧项目踩过的 P0 坑：信号 T 日收盘算、T+1 开盘成交，回测和实盘共用一套策略代码；成本模型唯一；涨跌停建模；Sharpe 和回撤算对；数据缓存双向校验；强制输出买入持有基准对照。
