# 技术专题

这五篇是十四个项目里**最有复用价值**的技术问题。它们不绑定某个具体项目，而是同一类问题在不同业务里反复出现的解法。

## 五篇专题

| 专题 | 核心问题 | 来自 |
| --- | --- | --- |
| [PDF 逆向解析](/engineering/pdf-parsing) | 没有文本层的版式 PDF，怎么还原成结构化表格 | 美鸥做账工具 |
| [内容质量门禁](/engineering/content-quality-gate) | AI 生成的内容，怎么自动判定能不能发 | GEO 内容系统 |
| [发布可靠性工程](/engineering/publishing-reliability) | 外部平台不可控时，怎么保证不重发、不漏发、失败可追 | GEO 系统 / RPA |
| [知识工程与 RAG](/engineering/knowledge-rag) | 知识怎么组织，才能让模型不胡说 | AI 智能客服 |
| [自动化安全边界](/engineering/automation-safety) | 脚本要动真实业务数据，怎么兜底 | RPA / 做账工具 |

## 一条贯穿的主线

这五个问题表面不同，底下是同一件事：

> **当系统要接入一个不可控的外部世界时，怎么保证它不闯祸。**

| 外部不可控因素 | 专题 | 应对思路 |
| --- | --- | --- |
| PDF 版式千变万化 | PDF 逆向解析 | 通用规则 + 特例补丁，分层处理 |
| LLM 输出质量不稳定 | 内容质量门禁 | 多层硬阈值，不信任单次输出 |
| 第三方平台会失败 | 发布可靠性 | 幂等 + 有界重试 + 可操作失败记录 |
| 模型会胡说 | 知识工程 | 限定知识边界 + 输出侧校验 |
| 脚本会误操作 | 自动化安全 | 默认 dry-run + 只读优先 |

**共同点：都不指望外部变可靠，而是在自己这一侧建防线。**

## 建议阅读顺序

- 如果你要面试**后端 / 数据方向**：PDF 逆向解析 → 发布可靠性 → 自动化安全
- 如果你要面试 **AI / 算法应用方向**：内容质量门禁 → 知识工程 → 发布可靠性
- 如果你只有五分钟：直接看 [自动化安全边界](/engineering/automation-safety)，它最能体现工程判断力

## 一个提醒

这五篇里写到的**失败案例和已知缺陷**，和成功经验一样重要。

面试时主动说出"这里我做得不够、应该这样改进"，比只讲成功更有说服力——因为只有真正跑过生产系统的人，才知道坑在哪。
