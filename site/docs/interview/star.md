# 用 STAR 讲项目

STAR = **S**ituation（情境）**T**ask（任务）**A**ction（行动）**R**esult（结果）。

这一页把**八个重点项目**拆成 STAR 结构（十四个交付物里挑面试最值得讲的），每个都附一句**追问钩子**——面试官顺着问的时候，你知道该往哪讲。

## 一、美鸥做账工具

| | |
| --- | --- |
| **S** | 亚马逊后台导出的财报是**无表格结构的版式 PDF**，12 个站点 × 多语言，财务每季度手工录入几百行科目和金额到 Excel 模板 |
| **T** | 把流程压成"选 PDF → 选模板 → 写入"，准确率要能支撑报税 |
| **A** | PyMuPDF 按坐标重建两栏表格；7px 窗口做行分组；为日文 11px 下漂做孤儿金额再分配；11 种语言关键词打分 + 字典精确匹配 + difflib 模糊匹配（0.80）；五种数字格式归一；映射对齐中国会计科目；5 条校验规则 |
| **R** | 12 国真实 PDF 测试全部通过；支持 11 语言 20 币种；延伸到亿企代账凭证导入，按国家×类别连续编号、sha256 防重复入账 |

**追问钩子**：「坐标聚类怎么处理的？」→ 讲 7px 窗口和日文孤儿金额，强调**通用规则与特例补丁分层**。

完整版：[美鸥做账工具](/projects/pdf-to-excel) ｜ 技术细节：[PDF 逆向解析](/engineering/pdf-parsing)

## 二、GEO 内容生产系统

| | |
| --- | --- |
| **S** | 内容获客靠人工写稿 + 手动分发到六个平台，慢，且**发完不知道有没有效果** |
| **T** | 让 AI 搜索引擎引用我们的内容，全流程自动化，且质量可控 |

## 四、美鸥天眼 · 关税查询

| | |
| --- | --- |
| **S** | 报关员查一个商品的关税和退税率，要在中国 HS、英国欧盟 TARIC、美国 HTS、商务部五个站点之间来回切 |

## 八、多策略实盘执行矩阵

| | |
| --- | --- |
| **S** | 量化研究最大的自欺是「同一段数据上调参、再报告同一段数据」。要让结论可信，必须**多套策略并行、资金隔离、逐笔落账**，而不是只挑最好看的那条曲线 |
| **T** | 4 套不同逻辑的策略跑在 5 个相互隔离的虚拟盘账户，每个交易日自动复盘，盈亏要能归因到"哪一类出场" |
| **A** | V4/V14 规则驱动 ETF 短线（24 只 ETF 分五品类独立参数 + 打分排名）；V17 每只 ETF 独立 XGBoost、21 维特征、每日盘前重训；TradingAgents 多角色研究→辩论→风控裁决；T+0 卫星仓独立风险额度。**工程治理是重点**：行情快照超 10 秒 fail-closed、LLM 只做研究**不碰下单闸门**（纯 Python 风控）、数据不可验证强制持仓不动、5 账户资金隔离做对照 |
| **R** | 125 笔逐笔入账。V4/V14：104 笔、胜率 66.3%、累计 +6,216、最大回撤 1.27%；V17：21 笔、胜率 33%、**−3,032（失败，已如实记录）**；TradingAgents 核心仓 −5.96%；T+0 同逻辑 4 万账户 −0.52% vs 20 万账户 +0.16% |

**追问钩子**：「你说四个策略，有几个是亏的？」→ 直接说 V17 和核心仓都在亏，然后讲 V17 的死因：**21 笔全部收盘强平、止盈止损一次没触发、模型预测概率全挤在 0.60–0.70 没有区分度**。能说清自己哪里输了，比"我的策略很赚钱"可信。

完整版：[多策略实盘执行矩阵](/projects/finance-trader) ｜ 技术细节：[自动化安全边界](/engineering/automation-safety)

## STAR 的注意事项

::: tip Result 一定要有数字，数字一定要准确
| ✅ 好 | ❌ 差 |
| --- | --- |
| "50 天 121 次发布，成功率 80%" | "发布了很多内容" |
| "11 种语言、20 种币种" | "支持多种语言" |
| "14 次真实幂等跳过" | "做了幂等" |
| "AI 收录率 28.6%，趋势下降" | "效果不错" |

**数字来自运行日志和代码常量，不是估的。** 说不准就别说，说"我记不清具体数字，但量级是……"也可以。
:::

::: warning Action 里要讲取舍，不只是讲做了什么
"我用了 PyMuPDF" 是流水账。
"我先试了 OCR 路线，确认文本层够用之后把 torch 依赖从打包里排除了" 才是 Action。

**讲你放弃的选项和原因，比讲你选了什么更能体现判断力。**

每个项目至少准备一个"我本来可以 X，但我选了 Y，因为 Z"。
:::
