# 交付计划书（路线图总览）

这 8 个系统不是孤立的练手项目，而是围绕**跨境电商「财务—通关—内容—作业—服务」全链路**做的一套一体化交付。下面把它们放在同一条演进路线上看，既能规划下一步，也能在面试时一句话讲清"我到底交付了什么"。

::: info 怎么读这张图
- **阶段一**是已经交付、在生产或运行中跑着的系统（对应各项目页的"真实状态"）。
- **阶段二~四**是计划书，把每个项目页"已知边界"里的问题，翻译成有优先级、有动作的下一步。
- 每张图都区分了**状态**：已交付 / 进行中 / 规划中 / 待启动 / 设想，不把"在做"说成"做完了"。
:::

## 一、一体化交付全景

```text
财务自动化      做账工具(PDF→Excel) ──→ 亿企代账凭证导入(规划中)
                              │
通关数据        美鸥天眼 · HS 编码 / 关税查询
                              │
作业与服务      跨境 SOP 视频平台 ──→ RPA 工具链(运单标识 + 物流对账)
                              │
内容获客        GEO 内容生产系统 ──→ GEO 网页矩阵(News 站 / 官网 / 模板)
                  │
服务闭环        AI 智能客服 ◀── 内嵌于 财税合规官网
                  │
沉淀资产        项目知识库与本站(把以上全部沉淀成可展示的作品集)
```

一条主线：**把跨境业务里最高人工、最易错、最重复的环节，逐个变成可运行、可度量、可审计的系统。**

## 三、阶段二：收口与上线（近期 1–2 月）

这一阶段的目标都是**把"半成品"变"成品"**，动作集中在文档对齐、合规去风险、容器化上线：

| 系统 | 近期计划 | 优先级依据 |
| --- | --- | --- |
| 做账工具 | README 与代码对齐（语言数 / 借贷平衡措辞）；桌面 V16/V17 开关进 GUI | 面试前最该做的低成本修正 |
| 美鸥天眼 | 核实并修正 classify 过时注释（"captcha bypass" 实为本地检索）+ 补离线测试；数据本地化仍按计划推进 | 注释/测试已补全，合规边界已厘清 |
| AI 智能客服 | Dockerfile / compose 容器化上线；集团版合并回 main | 从"可运行"到"已上线" |
| 财税合规官网 | 三套风格定版，接真实域 / DNS 上线 | 模板站 → 生产站的跨越 |
| GEO 内容系统 | 针对 `self_containment` 结构迭代，止住收录率下降 | 有测量手段才能治下降 |

::: warning 近期不要碰的事
**不要为了"看起来更完整"去编造未上线的系统。** 阶段二的成功标准是"已交付的更稳、半成品更诚实"，不是"项目数量变多"。
:::

## 四、阶段三：平台化（中期）

把"能用的工具"升级为"能扩展的平台"——这一步区分了"做了一个脚本"和"做了一套系统"：

| 系统 | 中期计划 |
| --- | --- |
| RPA 工具链 | 抽象「任务定义 + 参数 + 状态机」，统一调度（APScheduler / cron），失败重试；底座先补幂等、审计 |
| 美鸥天眼 | 核心 HS / 税率本地化（SQLite），抓取降级为定期同步；自研检索雏形 |
| GEO 内容系统 | `geo_agent_team` 从只读审计升级为带人工审批的半自动编排 |
| SOP 视频 | 二维码内置生成；核心服务补单测；多实例换 Postgres |
| 品牌官网 / 合规站 | `db/schema.ts` 从空到实，接 Drizzle 真实内容 |

## 五、阶段四：生态联动（远期设想）

这一步是"一体化交付"的终态——让 8 个系统互相喂数据，而不是各自为政：

- **做账 → 亿企代账**：PDF 解析输出的凭证直接驱动迁账软件（编排层规划中）。
- **SOP ↔ RPA ↔ 做账**：入库即建议 SOP，运单标识与对账闭环到财务。
- **GEO ↔ 客服**：AI 客服引用 GEO 系统最新文章，形成「内容—服务」闭环；合规官网成为 GEO 矩阵中被 AI 引用的一环。
- **追踪 → 选型**：用收录探针与爬虫观测数据，反向驱动官网风格选型与内容结构迭代。

## 六、一句话向面试官讲清

> 我交付的是一套跨境电商的「财务—通关—内容—作业—服务」自动化系统：做账工具把亚马逊财报 PDF 变成可入账 Excel，HS 编码系统聚合多国关税，SOP 视频和 RPA 工具链把仓内作业和运单操作自动化，GEO 内容系统和网页矩阵做面向 AI 搜索的内容获客，AI 客服和合规官网把服务与获客收口——并且我把这些项目连同复盘、边界和路线图，沉淀成了你正在看的这个作品集站。

::: tip 关于"计划书"本身的诚实
上面阶段二~四的状态都是**规划**，不是既成事实。面试时被问到"这个做了吗"，正确答法是：阶段一已经交付，阶段二正在收口，阶段三~四是下一步方向，每一条都对应一个现在已知的边界。把路线图当成"我对系统的判断和规划"来讲，比当成"已完成的功能清单"安全得多。
:::
